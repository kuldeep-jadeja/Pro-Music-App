Create `pages/api/admin/retry-jobs.js` as a POST-only admin endpoint.

**Method guard:** Return 405 `{ error: 'Method not allowed' }` for non-POST requests.

**Request body shape:** `{ jobIds: [string] }` where each string is a MongoDB ObjectId (`_id`) of an ArtistJob document.
- If `jobIds` is missing or not an array or empty, return 400 `{ error: 'jobIds must be a non-empty array' }`.

**Database connection:** Call `connectDB()` at the top of the handler before any Mongoose operations.

**Per-item processing loop** (sequential `for...of` — NOT `Promise.all`, preserves input order):

For each `jobId` in `jobIds`:

Step 1 — Validate jobId is a non-empty string:
```javascript
if (!jobId || typeof jobId !== 'string') {
  results.push({ jobId, status: 'failed', reason: 'invalid_job_id' });
  continue;
}
```

Step 2 — Atomic reactivation (QUEUE-04 core logic):
```javascript
let updated;
try {
  updated = await ArtistJob.findOneAndUpdate(
    { _id: jobId, status: 'failed' },
    {
      $set: {
        status: 'queued',
        queuedAt: new Date(),
        retriedAt: new Date(),
        error: null,
      },
    },
    { new: true }
  );
} catch (err) {
  // Invalid ObjectId format throws CastError
  results.push({ jobId, status: 'failed', reason: 'invalid_job_id' });
  continue;
}
```
The filter `{ _id: jobId, status: 'failed' }` means:
- If job exists AND status is 'failed' → updated is the updated document (proceed to enqueue)
- If job does not exist OR status is not 'failed' → updated is null (check which case)

Step 3 — Handle null return (job not found or not failed):
```javascript
if (!updated) {
  const job = await ArtistJob.findById(jobId).lean();
  if (!job) {
    results.push({ jobId, status: 'failed', reason: 'job_not_found' });
  } else {
    // Job exists but is queued or running (or done)
    results.push({ jobId, artistSpotifyId: job.artistSpotifyId, status: 'skipped', reason: 'already_active' });
  }
  continue;
}
```

Step 4 — Redis re-enqueue (after successful reactivation):
```javascript
const enqueued = await enqueueArtistExpand({
  artistSpotifyId: updated.artistSpotifyId,
  artistName: updated.artistName,
});
if (!enqueued) {
  // Redis failed — roll back the status to failed to prevent orphaned queued record
  await ArtistJob.findOneAndUpdate(
    { _id: jobId },
    { $set: { status: 'failed', error: 'redis_unavailable_on_retry', queuedAt: null, retriedAt: null } }
  );
  results.push({ jobId, artistSpotifyId: updated.artistSpotifyId, status: 'failed', reason: 'redis_unavailable' });
  continue;
}
results.push({ jobId, artistSpotifyId: updated.artistSpotifyId, artistName: updated.artistName, status: 'queued', reason: 'retry_queued' });
```

**Summary computation:**
```javascript
const summary = {
  total: results.length,
  queued: results.filter(r => r.status === 'queued').length,
  skipped: results.filter(r => r.status === 'skipped').length,
  failed: results.filter(r => r.status === 'failed').length,
};
```

**Response:** Always `res.status(200).json({ summary, results })` — HTTP 200 for mixed results.

**Export:** `export default requireAdmin(handler)`.

**Critical decision from CONTEXT.md:** "Retry reuses/reactivates the existing failed job record (no new record creation for retry)." — `findOneAndUpdate` on `{ _id: jobId, status: 'failed' }` enforces this. NEVER use `ArtistJob.create()` or `new ArtistJob()` in this file.
