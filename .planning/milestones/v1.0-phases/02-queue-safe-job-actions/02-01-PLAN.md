  <action>
Create `models/ArtistJob.js` as an ES module (import/export, matching all other models in this project).

Schema fields (exact names required by CONTEXT.md decisions and Phase 3 dashboard queries):
- `artistSpotifyId`: String, required: true, unique: true, index: true
  - This is the idempotency key. `unique: true` enforces ONE record per artist at DB level.
  - Concurrent upsert races that slip past the application-level check throw `MongoServerError E11000` (code 11000) — callers must catch this and treat as `already_active`.
- `artistName`: String, default: null
- `status`: String, enum: ['queued', 'running', 'done', 'failed'], default: 'queued', index: true
- `error`: String, default: null  (stores failure reason for Phase 3 dashboard VIS-03)
- `queuedAt`: Date, default: null
- `startedAt`: Date, default: null
- `completedAt`: Date, default: null
- `retriedAt`: Date, default: null
  (retriedAt is set when admin manually retries; distinct from queuedAt which is set on every enqueue)

Schema options: `{ timestamps: true }` (adds createdAt/updatedAt automatically, following Playlist.js).

Export pattern (same mongoose.models guard as all other models):
```javascript
export default mongoose.models.ArtistJob ||
  mongoose.model('ArtistJob', ArtistJobSchema);
```

Do NOT use `mongoose.Schema.Types.ObjectId` for any field in this model — ArtistJob has no foreign key references in Phase 2.

Include a JSDoc comment at the top explaining the model's role: per-artist expansion job state store, one document per artist (enforced by unique index), used by admin enqueue/retry endpoints and Phase 3 dashboard.

1. `export const ARTIST_EXPAND_QUEUE_KEY = 'demus:artist-expand:queue'`
   - MUST be a different key from `'demus:ytmatch:queue'` (worker isolation per SYNC-01 decisions)
   - MUST be a different key from `'demus:metadata:queue'` (separate concerns)

2. `export async function enqueueArtistExpand(job)`
   - `job` shape: `{ artistSpotifyId: string, artistName: string | null }`
   - Internally: calls `await getRedis()`, checks for null, calls `redis.rpush(ARTIST_EXPAND_QUEUE_KEY, JSON.stringify(job))`
   - Returns: `true` if enqueued, `false` if Redis unavailable or rpush throws
   - On `!redis`: logs `[ArtistExpandQueue] Redis unavailable — skipping enqueue` (use isDev guard for the warn)
   - On catch: logs `[ArtistExpandQueue] Failed to enqueue: {err.message}` (always log errors, no isDev guard)
   - NEVER throws — callers in enqueue-artists.js will check the boolean and mark items as failed

Import: `import { getRedis } from '@/lib/redis';`

Include isDev guard (`const isDev = process.env.NODE_ENV !== 'production'`) matching the pattern in redisQueue.js and metadataQueue.js.
